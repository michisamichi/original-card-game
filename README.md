Node.js 22で `npm run serve` を実行し、http://127.0.0.1:8080/ をブラウザで開く。外部npmパッケージ不要。新規GitHub Pagesへの静的配信はローカル対戦用（実公開未検証）。オンライン試験は下記の専用Nodeサーバーを使う。`npm test` で新ゲームの自動テスト。実ブラウザ用の別テストは `python tests/browser_smoke.py`（PlaywrightとChromiumが必要）。結果は docs/TEST_REPORT.md。

## 対戦とカード作成
- 1端末で2人交互に操作。対戦準備で両者のデッキを選択。ターン交代時に手札を隠す。対戦画面の青緑枠は使用・攻撃可能、橙色枠は対象選択可能。進行中の対戦は保存されない。
- 標準30枚、同名2枚まで。20枚固定の検証用モードも維持。24種類の組み込みカード、基本・登場死亡効果・秘策のプリセット。デッキ作成・編集・削除（最大12件）。自作カード最大80件。自作カードの名称・種類・マナ・攻撃力・体力・挑発・速攻・急襲・聖なる盾・疾風・生命奪取・猛毒・潜伏・呪文ダメージ＋1・発動条件・効果・対象・数値・追加効果を設定しプレビュー表示。カード図鑑とデッキ編集の絞り込みに対応。デッキで使用中のカードの削除は拒否。
- マナ0〜10、攻撃力0〜30、体力1〜30、効果数値1〜30は技術上限でありカードバランスを保証しない。

## 現行の暫定ルール
- プレイヤーHP30、手札上限10、場7体、マナ最大10。初期手札は先攻3枚・後攻4枚、最初の先攻ターンは追加ドローなし。各ターン開始時にマナ上限+1、全回復、1枚ドロー。山札切れ、HP0、降参で敗北。手札超過は墓地へ。マリガン・後攻補償・進化は未実装。
- ミニオンは原則1ターン1回攻撃、召喚ターン攻撃不可。速攻は例外（プレイヤーにも攻撃可）。挑発が存在する間は挑発のみ攻撃可能。スペルは挑発に制限されない。ミニオン同士は同時にダメージを受け、体力は持続。0以下で死亡し墓地へ。体力強化は最大値と現在値を同時に上げ、既存ダメージを維持。攻撃力・最大体力の実効上限は99、回復は最大体力まで。
- 秘策は独立したカード種別。自分のターンにマナを払い設置（最大3枚、同名同時設置不可）。相手ターンの攻撃宣言前、プレイヤーへの直接攻撃前、ミニオン使用後、スペル使用後のいずれかで自動発動。相手には枚数のみ、発動後は公開され墓地へ。複数は設置順に個別解決し、攻撃者・対象消滅や勝敗確定で残りを温存。最初の全体・ランダム効果の対象側の盤面が空なら秘策は温存。秘策による秘策誘発・手動割込なし。ミニオン使用後秘策は登場時/死亡時効果解決後、使用ミニオンが生存している場合。スペル使用後秘策はスペル解決後。攻撃回数は宣言時消費。
- 自動死亡効果: 死亡した全個体を除去してからターンプレイヤー側→相手側、各盤面順でFIFO処理。新しい死亡効果は末尾。カード生成・復活は未実装。1解決の発動キュー上限61件、追加効果を含め各レシピ最大2ステップ（超過時は操作全体を拒否）。勝敗確定後は停止。手札超過による墓地送りは死亡扱いしない。

## 効果エディター v0.1.14
- 発動条件: ミニオンは効果なし/登場時/死亡時/自分のターン開始時/自分のターン終了時、スペルは使用時、秘策は4種類の自動条件。効果はドロー・回復・ダメージ・攻撃力強化・体力強化・両方強化・攻撃力弱体化・体力弱体化・両方弱体化・一時的な攻撃力強化・直接破壊。対象の選択肢は条件と効果によって変化。死亡時・ターン開始終了時・秘策は手動対象なし。登場時の手動対象は召喚前に選ぶので召喚自身を含めない。全体効果は解決時の盤面（登場した自身を含む）を参照。手動対象なしの登場時効果は召喚のみ（追加効果も不発）、対象必須スペルは使用不可。
- 単一レシピ `ability: {when, operation, target, amount}` は従来通り利用できる。任意の `followUp: {condition, operation, target, amount}` を追加。condition は `always`（続けて実行）または `killed`（最初のダメージまたは直接破壊で敵ミニオンが1体以上死亡した場合）。後者は最初の操作がdamageまたはdestroyの場合のみ選択可能。プレイヤーへのダメージ、後続の死亡時効果による撃破は条件に含めない。複数撃破でも追加は1回。
- 追加効果は自動対象（自分プレイヤー、味方全体、敵全体、味方ランダム1体、敵ランダム1体のうち効果に適した対象）のみ。手動対象、イベント個体、さらに入れ子の追加効果を禁止。例: 2枚ドロー→3HP回復、敵選択対象に2ダメージ→撃破時1枚ドロー、死亡時全体ダメージ→撃破時HP回復。各ステップで死亡個体を除去してHP勝敗確認。最初の効果で勝敗確定したら追加は実行しない。追加効果はキューに入った死亡時効果より先に処理し、その後FIFOで死亡効果を解決する。全体対象ゼロは通常の空処理（最初の秘策全体対象なしの場合は温存）。
- 単一236構成（効果なし含む）、複合6,226構成（数値を除く合法な設定組合せ）。組み込み24種は今回変更なし。新効果は自作カードで利用可能。

## 弱体化・ランダム対象 v0.1.8（暫定仕様）
- 恒久弱体化は敵ミニオンの攻撃力、最大・現在体力、または両方に適用。攻撃力下限0、最大体力下限1、実効上限99。最大体力が実際に減少した分だけ現在体力も減少し、既存のダメージ量を維持。現在体力0以下で通常の死亡・死亡時効果処理。弱体化後の再強化と回復を許可。弱体化による死亡は「ダメージで撃破」追加条件には含めない。攻撃力0の新規攻撃は不可。秘策が宣言済み攻撃者を0にした場合は攻撃ダメージ0、反撃は通常通り（死亡なら攻撃中断）。能力値は符号付き補正値で保存し、実効値を検証。期間限定の攻撃力強化は下記の仕様で実装。
- ランダム対象は味方または相手の生存ミニオン1体。プレイヤーを含まない。盤面順と既存の状態内 xorshift32 乱数で決定（乱数値を候補数で剰余）。候補があれば1回消費し、空なら消費しない。UI手動指定は不可。状態コピー上で実行し、同一状態・同一操作から同一結果。通信上の乱数の秘匿・耐チート性は未実装。

## v0.1.19–v0.1.21 永続化・通信制限・自動再接続
